# ADR-004: Deliberate deviations from the specification

- **Status:** Accepted (living document; each milestone appends)
- **Date:** 2026-09-11
- **Context documents:** `docs/01`–`docs/10`

The specification is the source of truth (04 for names and signatures, 05 for behaviour). Where
the implementation differs on purpose, the difference and its reason are recorded here, so
reviewers can tell a decision from a bug.

## M1

| #   | Spec                                                                                                         | Implementation                                                                                                                                                                                                                                                                                                                                                                               | Reason                                                                                                                                                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | 05 §1: a data change resets the page index (`autoResetPageIndex`).                                           | A data change **clamps** the page index into range instead of resetting it to 0. Query changes (search, filters, sorting, grouping, page size) still reset per `resetPageOn`.                                                                                                                                                                                                                | Resetting on every data change breaks polling, optimistic updates and live data: the user is thrown back to page 1 every few seconds. Clamping keeps the page stable and still fixes the out-of-range case.                                                                                                                       |
| D2  | 05 §5: `autoResetExpanded` resets expansion on data changes.                                                 | By default, expansion resets only when grouping changes. It resets on every data change only when `autoResetExpanded: true` is explicitly set.                                                                                                                                                                                                                                               | Same reason as D1: row ids are stable (`getRowId`), so expansion survives refetches safely.                                                                                                                                                                                                                                       |
| D3  | 07 §4: "`#717680` on `#FAFAFA` meets AA".                                                                    | The classic header is 4.37:1, below AA (4.5:1). The classic preset keeps the Skimmer colours 1:1; the other presets pass. The e2e axe check excludes `[data-theme="classic"] .tk-header-cell` from `color-contrast` only (`CLASSIC_HEADER_CONTRAST_EXCEPTION`). The search hotkey hint, which is not a Skimmer element, uses the plain surface so it passes.                                 | Parity is the purpose of the classic preset; the claim in 07 is arithmetically wrong. Use `light` (the default) for AA.                                                                                                                                                                                                           |
| D4  | 07 §6: the token lint covers every themed property.                                                          | The lint covers colour, border, radius, shadow and typography properties and bans colour literals in `theme.css`. Layout properties (padding, gap, sizes) may use literals where no token exists.                                                                                                                                                                                            | Tokenising every spacing value would add dozens of tokens with no theming use.                                                                                                                                                                                                                                                    |
| D5  | 07 §2 token list.                                                                                            | Additional tokens: `color.surfaceSubtle`, `space.stateY`, `control.searchWidth`, `pagination.navPadding`, `pagination.compactItemSize`.                                                                                                                                                                                                                                                      | Needed to express the classic preset without literals.                                                                                                                                                                                                                                                                            |
| D6  | 09 §4 bundle budgets.                                                                                        | See ADR-003.                                                                                                                                                                                                                                                                                                                                                                                 |                                                                                                                                                                                                                                                                                                                                   |
| D7  | 01 §5.1: the Skimmer page constrains the table to `calc(100vw - 210px - 40px)` next to its sidebar.          | Not reproduced on the demo site; the site's own layout is used.                                                                                                                                                                                                                                                                                                                              | That width comes from the Skimmer app shell, not from the table.                                                                                                                                                                                                                                                                  |
| D11 | 09 §5 gate 7 / 08 §6.5: "CI fails if a public symbol lacks a TSDoc description".                             | Every exported function, class, interface, type alias, variable, method and named interface member is documented and enforced. Callbacks nested inside a slot's **anonymous** prop bag (`SlotPropsMap.SearchInput.__type.onChange` and ~37 like it) are not individually documented; the slot itself carries the description, and the callbacks are listed with their types on `/api/slots`. | TypeDoc reports each member of an inline object type as a separate symbol. Documenting `onChange` on every one of ~55 slots adds noise without telling a reader anything the slot's own description and signature do not. The named API surface — options, column defs, instance, rows, columns, cells, hooks — is fully covered. |
| D10 | 05 §13: the cards layout shows "label/value pairs from the visible columns".                                 | The label is the column's `header` when that is a plain string, otherwise the column id. A `header` that is a render function or element is not used as a card label.                                                                                                                                                                                                                        | A card has no header row, so a header rendered as JSX (icons, tooltips, sort buttons) cannot be reused as a `<dt>`. Give such a column a string `header`, or replace the card with `responsive.renderCard`.                                                                                                                       |
| D9  | 05 §4.1: `infinite` loads the next page "when a sentinel row enters the viewport (IntersectionObserver)".    | The next page loads when the scroll position comes within 300px of the end, using a passive scroll listener on the bounded container (or the window when the table is not bounded).                                                                                                                                                                                                          | With virtualization the sentinel row is not in the DOM, so an IntersectionObserver on it would never fire. The observable behaviour — pages appended as you approach the end, working with virtualization — is the same.                                                                                                          |
| D8  | 05 §5 / §16: selected rows get `aria-selected`, hierarchical rows get `aria-level`, on a semantic `<table>`. | Those row states are only valid inside a grid (ARIA 1.2), so the `<table>` also takes `role="grid"` when row selection is enabled, and `role="treegrid"` when tree data or grouping give rows a depth. A plain table keeps the implicit table role.                                                                                                                                          | Without it axe reports a serious `aria-conditional-attr` violation, and screen readers ignore the state. Keyboard grid navigation, which those roles imply, is specified in 05 §15 and lands in M5.                                                                                                                               |

## M6

| #   | Spec                                                                           | Implementation                                                                                                                                                                                                                                                                                                                                                           | Reason                                                                                                                                                                                                                                                                                       |
| --- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D12 | 08 §1: the site has **Ctrl+K search** over headings, API symbols and examples. | The palette answers Ctrl+K on every page **except** where a table has already claimed it. A `DataTable` with `searchHotkey` registers the same combination on `document`, which bubbles before the palette's `window` listener, so the palette stands down when the event was already handled. The topbar **Search** button opens it anywhere, including on those pages. | 05 §2 gives each table its own scoped search hotkey, and the parity screens use `mod+k` for it, so on every example page both features want the same keys. Deferring to the table matches where the user is actually working, and keeping the button means the palette is never unreachable. |
